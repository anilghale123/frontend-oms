# Design System — OMS

> Every new Claude Code session reads this file (it is imported from CLAUDE.md).
> Values below were read from the codebase (2026-10-04). When code changes, update them here; never guess.

## 1. Origin
- **Base:** Radian design system. The team uses it across projects.
- **Source of layout:** the app shell (sidebar, navbar, page container) is harvested from the old Meat-Management project (github.com/RamKatwal/Meat-Management).
- **Stack:** Next.js 16 (App Router), React 19, TypeScript. Tailwind CSS v4 with CSS-variable tokens declared in `@theme` (no `tailwind.config`). Radian UI components (Radix-based, added with the Radian CLI and configured in `components.json`), TanStack Query and Table, react-hook-form with zod, and Lucide icons.

## 2. Where things live
- **Design tokens:** `src/app/globals.css` (semantic tokens, status and theme remaps, light and `.dark`, font and heading utilities) and `src/app/utility.css` (raw Radian color scales such as `red`, `orange` and `emerald`, each with `-fg/-accent/-focus/-border/-hover/-text`). Use the semantic tokens; raw scales are only for building them.
- **Base UI components:** `src/components/ui` (Radian primitives; add with the Radian CLI, never hand-write or fork). Compositions go in `src/components/layout`, `src/components/data-display` and `src/components/feedback`, split by purpose (documented in `docs/components.md`).
- **Layout / app shell:** `src/components/layout` (`AppShell`, `AppSidebar`, `AppHeader`, `NavMain`), wired in `src/features/shell` (`MerchantShell`, `RiderShell`). Merchant sidebar sections come from `merchantNav` in `src/config/nav.ts`.
- **Page-level feature components:** `src/features/orders/components/queue` (Order Queue) and `.../detail` (Order detail); shared order pieces sit in `src/features/orders/components`. Rider portal: `src/features/delivery-validation`.
- **Icons:** Lucide only (`lucide-react`), Radian UI's icon library (`iconLibrary: "lucide"` in `components.json`). This covers nav and surface icons as well as UI glyphs. Radian primitives size them (the sidebar button sets `[&>svg]:size-5`), so don't add custom icon sets or sizes.

## 3. Tokens (use these, never raw values)
### Color
Use as Tailwind classes (`bg-*`, `text-*`, `border-*`, `ring-*`). Every token has a light and a `.dark` value.
- **Surfaces:** `bg` (cards, panels), `fill1` (app background, table footer, tile backgrounds), `fill2`–`fill4` (stronger fills, hover), `fill*-alpha` (translucent fills), `card`/`popover` (`elevation-level1/2`), `sidebar*` (sidebar only).
- **Text:** `fg` (primary text), `fg-secondary` (labels, muted text), `fg-tertiary` (hints), `fg-disabled`, `fg-inverse`.
- **Lines:** `border` (all borders and dividers; also the default border color), `alpha`.
- **Accent:** `primary` (primary actions, active states) with `primary-fg` (text on primary), `primary-accent` (soft background, active row), `primary-focus`, `primary-border`, `primary-hover` and `primary-text`. The appearance theme remaps it through `html[data-theme]`; the default is Violet Blue.
- **Status:** `info`, `success`, `warning` and `error`, each with the same `-fg/-accent/-focus/-border/-hover/-text` steps. Order status colors come only from `StatusBadge` (section 6).
- **Brand:** `brand`/`brand-fg` (Fonepoints red #D12427): logo and the opt-in `fonepoints` accent theme, never status.

### Typography
- **Family:** Geist Sans (`next/font`, `--font-body`/`--font-heading`); Inter or Roboto can be picked in Settings → Appearance (`html[data-font]`). Mono: Geist Mono.
- **Scale (Tailwind defaults):** `text-xs` for hints, captions, `DetailField` labels and badges; `text-sm` for body, tables, controls and panel titles (the default); `text-base` for page titles (`PageHeader` `h1`, semibold) and size 44/48 controls; `text-lg` and up are rare.
- **Weights:** `font-medium` for emphasis and `font-semibold` for titles. `tabular-nums` for counts, IDs and money.
- `heading-1`…`heading-6`, `body-15` and `body-13` utilities exist in `globals.css` (Radian's type scale). Only `heading-6` (20px semibold) is used, for the `StatTile` value and the Radian `Card` title; OMS screens otherwise use the Tailwind sizes above.

### Spacing / radius / shadow
- **Spacing:** the Tailwind default scale (`--spacing: 0.25rem`, 1 step = 4px); no custom spacing tokens. Use `gap-*` on flex and grid containers rather than margins.
  - `gap-0.5`–`gap-2` (2–8px): inside a component (icon + label, badge + text, button groups).
  - `gap-3` / `px-3` (12px): label to value, toolbars, page header to body (`Page`).
  - `p-4` / `gap-4` (16px): card padding (`PanelContent`) and between sections (`PageBody`).
- **Control sizes:** Radian controls take `size` = height in px (`28`, `32`, `36`, `40`, `44`, `48`), which sets their padding, gap, font size, icon size and radius. Don't add padding to them. Use 32 in toolbars, tables and the pagination footer; 28 for compact icon buttons; 44/48 for rider touch targets.
- **Radius:** the Tailwind defaults. `rounded-xl` for cards (`Panel`) and the content card; `rounded-lg` for size 36+ controls; `rounded-md` for small controls, chips and badges; `rounded-full` for avatars, dots and the tracker circles.
- **Shadow:** mostly flat. Cards use `ring-1 ring-border`, not a shadow. `shadow-sm` is only on the inset content card and the floating sidebar; overlays (popover, menu, dialog) bring their own shadow from Radian.

## 4. Components available
**Radian primitives** (`@/components/ui/<name>`): `Button`/`IconButton` (variants `strong`, `soft`, `outline`, `ghost`, `link`; colors `primary`, `neutral`, `info`, `success`, `warning`, `error`), `Input`/`InputWrapper`, `TextArea`, `Select`, `Checkbox`, `RadioGroup`, `Switch`, `Label`, `Form` (react-hook-form field with label and error), `Badge` (`strong`/`soft`/`outline`, sizes 20/24/28), `Table`, `Tabs`, `ToggleGroup` (status filter rows), `Dialog`, `AlertDialog` (confirming one-way actions), `Drawer` (bottom sheets, e.g. QR scan), `Popover`, `DropdownMenu`, `Tooltip`, `Accordion`, `Alert`, `Avatar`, `Calendar`, `Pagination`, `ScrollArea`, `Skeleton`, `Spinner`, `Stepper`, `Empty`, `Card`, `Sidebar`, plus less-used ones in the folder.

**Shared components** (`@/components/layout`, `@/components/data-display`, `@/components/feedback`; props in `docs/components.md`): `Page`/`PageBody`, `PageHeader` (title, count, badge, actions, `back`), `Panel`/`PanelHeader`/`PanelContent`, `DataTableCard`/`DataTable`/`useDataTable` (toolbar, sticky header, loading, empty, error and pagination), `EmptyState`, `ErrorState`, `StatTile`, `ExportMenu`, `CopyButton`, `NavTabs`, the shell (`AppShell`, `AppSidebar`, `AppHeader`, `NavMain`, `MobileShell`).

**OMS features** (`@/features/orders` and others, imported through each feature's `index.ts`): `StatusBadge`, `DetailField`, `OrderProgressTracker` (fulfillment stepper), `OrderActivityList` (activity timeline), `OrderSidePanel`, `OrderListPanel`; `MarkReadyDialog`/`AssignRiderDialog` (`features/fulfillment`); `DeliveryValidationForm`, `AttemptsCounter`, `QrScanSheet` (`features/delivery-validation`).

**Not built yet:** Toast. There's no toast primitive; `CopyButton` uses a tooltip instead. Add one through the Radian CLI and record it here when it's needed.

(`ORDER_STATUS_BADGE_COLOR`).

## 7. Figma readiness
- Component and variant names in code must match their future Figma names (e.g. `Button/Primary/Default`).
- Use tokens only. A value that does not exist as a token cannot map to a Figma variable.
- Keep components presentational. Data fetching stays in page or container components.

## 8. Don'ts
- No hex, rgb or arbitrary Tailwind values (`text-[13px]`, `bg-[#...]`).
- No new UI library without recording the decision below.
- No duplicate components (e.g. a second Button).
- No copy in ALL CAPS labels. Use sentence case and active verbs ("Assign rider", "Mark ready").
