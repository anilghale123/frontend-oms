# Architecture

## Folder map

Two surfaces only: **merchant** (sidebar dashboard) and **rider** (mobile delivery portal).
Merchant has one module, OMS, with two pages: Order Queue and Order detail. Home and Settings
are placeholders that round out the sidebar.

```
src/
  app/
    (merchant)/                     # Merchant surface (sidebar dashboard)
      layout.tsx                    # MerchantShell
      page.tsx                      # /          Home (placeholder)
      settings/page.tsx             # /settings  Settings (placeholder)
      orders/                       # OMS
        page.tsx                    # /orders               Order Queue
        (detail)/layout.tsx         # keeps the order list panel mounted between orders
        (detail)/[omsOrderId]/page.tsx   # /orders/[id]     Order detail
    (rider)/                        # Rider portal, mobile-first, no sidebar
      layout.tsx                    # RiderShell
      deliver/page.tsx              # /deliver  Confirm delivery
    embed/                          # Embedded surface, framed by the Fonepoints portal
      layout.tsx                    # HostChannelProvider + AuthProvider + HostSync + gate
      orders/…                      # the same pages, no chrome of their own
    api/
      session/route.ts              # POST token → httpOnly cookie · GET session · DELETE revoke
      session/_cookie.ts            # the cookie's name and flags, decided once
      session/_verify.ts            # asks the OMS backend who a token belongs to
      session/dev/route.ts          # development-only mint, for working without the portal
      oms/[...path]/route.ts        # the proxy: reads the cookie, attaches the Bearer
    api/mock/                       # Route handlers imitating OMS APIs — the no-backend fallback
      orders/route.ts               # POST create (idempotent), GET list
      orders/[omsOrderId]/route.ts
      orders/[omsOrderId]/status/route.ts
      orders/[omsOrderId]/rider/route.ts
      validate/route.ts             # rider voucher validation
      dev/                          # prototype backdoors used by the rider portal
        voucher/[omsOrderId]/route.ts   # simulated QR scan
        delivering/route.ts             # "Simulate delivery" shortcut
    layout.tsx                      # providers, fonts
  components/
    ui/                             # tier 1: Radian primitives (generated by CLI)
    layout/                         # tier 2: screen structure + navigation (docs/components.md)
    data-display/                   # tier 2: tables, metrics, export
    feedback/                       # tier 2: empty, error, confirmation
    icons/                          # Fonepoints logo
  features/                         # tier 3: OMS-specific
    shell/                          # MerchantShell, RiderShell, ShellHeader
    orders/                         # merchant OMS pages
      components/
        queue/                      # Order Queue page: columns, status tabs, date filter, row action
        detail/                     # Order detail page: list panel, tracker, item, side panel…
        status-badge.tsx            # shared by both pages (and other features)
        detail-field.tsx
      hooks/  api.ts  export.ts  index.ts
    fulfillment/                    # Mark ready + Assign rider dialogs, rider form schema
    delivery-validation/            # rider portal: form, QR scan, attempts counter
  lib/
    domain/                         # pure TS: types, status machine, permissions, rules
    api/                            # fetch client, contracts, query keys
    auth/                           # session shapes + the in-memory token fallback
    host/                           # the postMessage protocol and channel to the portal
    mock/                           # in-memory db, seed, Fonepoints simulator
    nav/                            # generic route matching + breadcrumbs (no config)
    utils/                          # formatting (points, money, dates), export
  providers/                        # QueryProvider, HostChannelProvider, AuthProvider, HostSync
  config/                           # nav (typed routes per surface), constants, server-env
```

Where to look: a merchant page → `features/orders/components/<queue|detail>/`; a rider screen →
`features/delivery-validation/`; a business rule → `lib/domain/`; mock behavior → `lib/mock/`.

## Layers and dependency direction

`app → features → lib`. Never the reverse. Enforced by `eslint.boundaries.mjs`.

| Layer | May import | Must not import |
|---|---|---|
| `app/` (pages) | features, components, lib/api, lib/domain | lib/mock (except `app/api/mock`) |
| `app/api/mock/` | lib/mock, lib/domain, lib/api/contracts | features, components |
| `features/<x>/` | components, lib/api, lib/domain, other features via `index.ts` | lib/mock, deep paths into other features |
| `components/ui` | lib/utils | anything else |
| `components/{layout,data-display,feedback}` | components/ui, lib/utils, lib/nav, sibling tier-2 folders | features, config, providers, lib/api, lib/domain, lib/mock |
| `lib/domain` | nothing but other lib/domain files | React, Next, anything else |

## Feature folder shape

```
features/<name>/
  components/     # React components for this capability
  hooks/          # TanStack Query hooks (use-orders.ts → useOrders…)
  api.ts          # thin wrappers over lib/api client for this feature
  schema.ts       # zod schemas for this feature's forms
  index.ts        # public exports — the only import path for other code
```

## Naming

- All file names are kebab-case, matching what the Radian CLI generates:
  `@/components/ui/button`, `layout/page-header.tsx`, `features/orders/components/status-badge.tsx`.
- Exports are PascalCase components (`Button`, `StatusBadge`), one component per file.
- Hooks: file `use-x.ts`, export `useX`. Schemas: `xSchema`. Query keys: `queryKeys.orders.detail(id)`.
- Route params use domain names: `[omsOrderId]`, never `[id]`.

## The backend, and the mock it replaced

`src/lib/api/client.ts` reads `NEXT_PUBLIC_OMS_API_BASE`, which now defaults to `/api/oms` — this
app's own proxy, which reads the access token from an httpOnly cookie and forwards to the OMS
backend (`oms-backend`, port 3001). Request and response shapes live in
`src/lib/api/contracts.ts` and are honoured by both, so the swap was a configuration change.

The mock at `src/app/api/mock` was kept. Set `NEXT_PUBLIC_OMS_API_BASE=/api/mock` and the app runs
with no backends and no session at all, which is still the quickest way to work on a screen.

Two contract changes came with the real backend, both removing something the client used to be
trusted with: the order list no longer takes `?merchantId=` (the token decides), and a status
change no longer carries `actor`/`actorRole` (the backend derives them from the token). See
`docs/auth-handoff.md`.
